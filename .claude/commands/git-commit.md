# /git-commit

## 형식

```
<type>(<scope>): <한 줄 요약 — 한국어>

<본문 — 한국어>
```

- `type`: feat / fix / refactor / perf / style / docs / chore / test
- `scope`: `components` `styles` `packaging` `docs` `claude` 등. 생략 가능
- 요약은 명령형·현재형. 마침표 없음

## 본문에 쓰는 것

**무엇을 했는지가 아니라 왜 그렇게 했는지**를 쓴다. 특히:

- 겉으로 드러나지 않는 결함을 고쳤다면 **어떻게 발견했는지**
- 설계 판단을 했다면 **버린 대안과 그 이유**
- 공개 API 가 바뀌었다면 **소비자에게 미치는 영향**
- 알려진 제약·보류 사항

변경 파일 목록은 쓰지 않는다 (`git show --stat` 으로 볼 수 있다).

## 절차

1. `git status` / `git diff` 로 실제 변경을 확인한다
2. 관련 없는 변경이 섞여 있으면 사용자에게 분리할지 묻는다
3. 커밋 메시지 마지막 줄에 세션 링크를 넣는다
4. **`git push` 는 하지 않는다** (deny 에 등록되어 있다)

## 하지 않는 것

- 사용자가 요청하지 않았는데 커밋하지 않는다
- 검증(typecheck / verify:pkg)이 실패한 상태로 커밋하지 않는다.
  실패한 채로 커밋해야 한다면 그 사실을 본문에 명시한다
