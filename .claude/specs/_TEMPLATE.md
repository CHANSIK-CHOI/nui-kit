## 1. 개요

무엇을 하고 어디에 쓰는지 1~2문장. 비슷한 컴포넌트가 있으면 **언제 이걸 쓰고 언제
저걸 쓰는지** 구분을 적는다.

### 라이브러리 등록 근거 (design-system.md §7 — 6조건)

| 조건 | 내용 |
| --- | --- |
| 반복 수요 | |
| 책임 소유 | 상태·구조·표현 중 무엇을 소유하는가 (한 문장) |
| 토큰 적합성 | 매트릭스로 표현되는가. 새 색이 필요하면 합의 결과 |
| 변형 예산 | variant 축 수 (3개 이하) |
| 상태 정의 | 해당하는 상태와 **해당 없는 것의 근거** |
| 검증 가능 | 문서 데모와 브라우저 확인 방법 |

> 이식된 컴포넌트는 "원본에서 이식"이라고만 적어도 된다.

## 3. 공개 API

### 3-1. Props

| prop | 타입 | 기본값 | 설명 |
| --- | --- | --- | --- |

**값 소유권** — controlled / uncontrolled, 무엇을 소비자가 소유하는가.
`defaultValue` 를 `Omit` 했다면 그 이유 (rules/components.md §5).

**받지 않는 prop** — 타입에서 제외한 것과 이유. 특히 "타입은 통과하는데 동작만
없거나 어긋나는" 것을 닫았다면 반드시 적는다.

### 3-2. 합성 구조

| dot notation | named export | 렌더 |
| --- | --- | --- |

> RSC 에서 dot notation 은 `undefined` 가 된다. named export 를 반드시 동반한다
> (rules/components.md §2). 합성이 없으면 "없음".

### 3-3. 배럴에서 나가는 것

컴포넌트 외에 타입·헬퍼·훅을 공개한다면 목록과 이유.

## 9. 스타일

> **색·상태 토큰은 [design-system.md](../rules/design-system.md) §3 매트릭스를 따른다.**
> 여기에는 **매트릭스로 설명되지 않는 것만** 적는다. 토큰을 다시 나열하지 않는다.

- **분류**: 입력 컨트롤 / 선택 컨트롤 / 표면 / 액션 중 무엇인가
- **너비**: `100%` / 자기 치수 / 내용 폭 (design-system.md §5)
- **공개 훅**: `--nui-{name}-*` 목록과 기본값
- **매트릭스 예외**: 매트릭스와 다르게 처리한 것과 **그 이유**
- **고유 치수**: 이 컴포넌트만 쓰는 값
